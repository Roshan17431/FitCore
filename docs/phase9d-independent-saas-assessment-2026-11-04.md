## Hosting and CI findings

The current [render.yaml](../render.yaml) is a legacy/free backend template: liveness path, old CORS and no separate database/deploy hold. Its stale `JPA_DDL_AUTO=update` entry is **not consumed** by current application.properties, which hardcodes validate. Do not claim Hibernate update currently runs; do not apply this template to the new SaaS.

Root/frontend Vercel guards disable Git deployment for main/master only; unspecified branches are not universally disabled. Existing project settings, deploy hooks and integration permissions were not accessed. New projects need their own initial all-branch hold and no shared secret groups. Vercel functions cannot assume access to Render's private network. [Vercel Git behavior](https://vercel.com/docs/project-configuration/git-configuration), [Render private network](https://render.com/docs/private-network).

A verified platform mismatch remains: Render internal PostgreSQL does not support verify-full. The design requires an explicitly certified authenticated-TLS topology; see the [infrastructure TLS gate](phase9d-infrastructure-configuration.md). No internal verification exception is approved. [Render connection contract](https://render.com/docs/postgresql-creating-connecting#ssl-modes-for-internal-connections).

## Threats and proposed controls

| Threat | Proposed control / test |
| --- | --- |
| XSS steals a durable bearer | No browser bearer in recommended mode; HttpOnly cookie, CSP/escaping/dependency review; script injection cannot read session handle. XSS can still issue requests: CSRF is not an XSS cure. |
| CSRF/login fixation | Framework synchronizer CSRF plus exact Origin/Fetch Metadata, host-only cookie, rotate preauth→authenticated session; malicious-site login/reset/write attempts fail. |
| Gym ID or role forgery | Reuse current actor/account validation and every scoped repository/reference check; no client tenant selector, proxy assertion role or cookie attribute grants authority. |
| BFF bypass/IP spoofing | Authenticated fixed-upstream gateway; sanitize headers and sign trusted client identity; direct Render business request without gateway proof fails. |
| Signed “approval” supplied by attacker | Protected trust roots plus independent release/workload authorization, expiry/replay/target/config/artifact binding; invalid permit causes zero DB attempts. |
| Correct schema on wrong DB | Canonical preconnect target allowlist + verified TLS + independent resource attestation + post-connect database/schema/login identity; hashes alone never authorize. |
| Restored state revives access/mail | External epoch/target reauthorization, session/JWT/challenge revocation, restored-account fresh-login hold and independent reactivation, outbox quarantine, provider receipt and suppression reconciliation. |
| Outbox timeout after acceptance | Stable frozen request/key, bounded deadline inside provider TTL, fenced retries; unknown beyond deadline requires operator reconciliation, never a fresh key. |
| Abusive owner sends many invitations | Atomic issuer/gym/recipient/provider quotas, suppression, bounded workers and audit; limits shared across instances. |
| Compromised runtime/publisher | Runtime cannot migrate or approve release; separate signer/operator/migrator/key custody. A fully compromised release authority/host remains a stated trust-boundary risk, not solvable by a DB comment. |

## Independent review resolution

The source/security and fresh builder reviews identified and resolved four design issues before handoff: restored credentials could authorize a fresh login despite token revocation; admitted invalid authentication attempts must not roll their abuse counters back; current API-base validation is only nonempty, not an absolute/HTTPS validator; and JavaScript generation checks cannot order browser Set-Cookie delivery. The final proposal therefore includes all-restored-account authentication holds with independent reactivation, distinct ingress-versus-issuance transactions, corrected source facts and an explicit cookie-writer/serialization/uncertainty/browser-support contract. The builder found no important unstated local-planning question after those changes. This is engineering review of a proposal, not owner approval or operational certification.
